# 游戏版本

五个版本保留同一套核心玩法。A–D 以原版为起点，分别增加或删减机制；目前 A 增加连击计分，B 是简化版，C 将组装改为 QTE，D 将煎台改为单肉饼曲柄进度玩法。

## 变体 A：连击

正确完成一个订单，连击数增加 1。1–4 连击为 ×1.0，5–9 为 ×1.1，10–14 为 ×1.2，15–19 为 ×1.3；之后每 5 单增加 0.1，暂不设上限。达到门槛的那一单立即享受新倍率。

每单得分 = 原有订单得分 × 高峰倍率（如适用）× 连击倍率，最后四舍五入为整数；不放大已经累计的总分。
交错单或任何一张订单超时都会立即清零连击，倍率回到 ×1.0；扣分仍按原规则，不乘连击倍率。肉饼烧焦、机器卡住、缺料和无效按键不打断连击。高峰开始/结束、切换工位也不清零。
右上角在所有工位显示 `COMBO` 数量及倍率；倍率达到 ×1.1 后反色显示。新开局从 0 连击开始。

## 变体 B：简化版

组装台只保留肉排、American Cheese、番茄、生菜和酸黄瓜。九张英文菜谱都由 2–5 份食材组成，所有菜谱都需要肉排。

绞肉机开局为空；没有生肉时会弹出英文提示，要求玩家按下方向键装肉。绞肉库存首次达到 300 时会弹出英文提示，要求玩家按右方向键前往煎台。达到阈值的提示会一直保留，直到玩家切换到煎台；之后本局不再重复。

## 变体 C：组装 QTE

组装台不再显示食材选择轮，也不允许自由选择放置顺序。玩家按菜谱顺序完成当前英文 QTE 提示；组合输入可以在 0.65 秒内先后完成。

肉饼为摇动曲柄，生菜为 **A**，番茄为 **下**，酸黄瓜为 **B**；洋葱为 **A+下**，鸡蛋为 **B+下**，蘑菇为 **曲柄+下**，培根为 **曲柄+A**，American Cheese 为 **曲柄+B**，English Cheese 为 **A+B**。放上层面包固定为 **上+A**，上菜固定为 **上+B**。游戏内提示全部使用英文。

## 变体 D：曲柄煎肉

煎台一次只放一块肉饼。按 **下** 消耗 50 份绞肉并放入肉饼，往复摇动曲柄才会推进屏幕顶部的进度条；时间本身不会推进烹饪。进度为 60–80 时可按 **上** 收取，超过 80 会烤焦，再按 **上** 丢弃焦肉。游戏内提示使用英文。

| 菜单名称 | 版本 ID | 玩法代码和配置 |
| --- | --- | --- |
| ORIGINAL（原版） | original | `source/` 下的原有玩法文件 |
| ORIGINAL VARIANT A（原版变体 A） | variantA | `source/variants/variantA/` |
| SIMPLIFIED（简化版） | variantB | `source/variants/variantB/` |
| ASSEMBLY QTE（组装 QTE） | variantC | `source/variants/variantC/` |
| CRANK GRILL（曲柄煎肉） | variantD | `source/variants/variantD/` |

开始菜单按 **B** 打开版本选择，**上/下** 移动，**A** 确认，**B** 取消。
确认后回到所选版本的开始菜单，转动摇柄开始游戏。星号标出当前版本。
游戏中通过系统菜单的 **versions (new game)** 返回选择界面，这会结束当前局并重新开始。
正常启动默认原版；选择其他版本会重启 Lua 运行时，只导入所选版本的玩法代码。

## 修改约定

- 只编辑目标版本目录内的文件。每个变体都有自己的 `main.lua`、`playerConfig.lua`、食谱、订单、计分、工位、提示和动画代码。
- 目录是一次性复制的独立源代码，不是构建产物；构建不会从原版重新生成或覆盖它们。原版的后续玩法修改也不会自动传播到变体。
- 变体的内部 `import` 必须指向自身目录，例如 `import "variants/variantA/playerConfig"`。不要导入原版或其他变体的玩法模块。
- 共享部分只有 SDK、版本入口（`gameVersions.lua`）、标题/加载界面及当前位图资源。改动这些共享部分会影响所有版本。
- 若某一变体需要不同的图片，新增到 `source/resource/variants/variantA/` 等专属目录，再修改该变体的资源路径；不要覆盖公共图片。
- 当前游戏没有进度存档。后续增加存档时使用 `GameVersions.savePath("progress")` 等路径，例如 `versions/variantA/progress`，并按 SDK 要求创建父目录。不要共用存档键。
- 如果明确要将一个修复应用于多个版本，逐个修改并验证，避免整目录同步覆盖已经分化的机制。

## 验证

`pdc -k source /private/tmp/bun-rush-versions.pdx` 构建同一个包含五个入口的游戏包。

`tests/titleScreen/run.py` 覆盖开场、菜单选择、取消、摇柄输入隔离、版本切换及进入游戏。
设置 `BUN_RUSH_TEST_VERSION=variantA`（或 B/C/D）可验证相应的真实入口和导入路径。
`tests/gameVersions/run.py` 检查玩法依赖隔离，并实际运行每个版本的配置、订单和计分模块。

`tests/combo/run.py` 验证 A 的连击门槛、倍率叠加、超时/错单清零，以及其他四版计分不变。
`tests/combo/main.lua` 是 SDK 集成测试入口，验证真实组装交单、防重复提交、烧焦不断连和 HUD 显示。

`tests/qte/main.lua` 覆盖 C 的全部食材 QTE、超时组合、上层面包和上菜组合键。

`tests/crankGrill/main.lua` 覆盖 D 的单肉饼限制、曲柄进度、60/80 收取边界和焦肉丢弃。
